# 3D 真人皮套直播

这个分支在原项目的弹幕、礼物、记忆和 TTS 链路上增加本地 3D 渲染。默认页面为 3D 控制台，原 Live2D 页面在 `/avatar2d`，原采集器仍向 `/api/danmaku` 发送事件。

## 1. 启动

需要 Python 3.10+、Node.js 22.12+，以及支持 WebGL 2 的浏览器。macOS 默认使用系统 `say`，Windows 默认 SAPI，Linux 需要先安装 Piper 与音色。

```bash
python3 tools/setup_3d.py
```

Windows 使用 `python tools/setup_3d.py`。脚本创建 `.venv`、安装 Python/npm 依赖、构建前端；仅在 `.env` 不存在时从模板复制，不覆盖已有密钥。也可手动执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm ci
npm run build
cp .env.example .env  # 仅首次；已有 .env 不要覆盖
.venv/bin/python bridge.py
```

Windows 把 Python 命令换成 `.venv\Scripts\python.exe`。打开 `http://127.0.0.1:8000`，点击「开启声音」。先用「直接朗读」发送自己输入的内容，确认声音、字幕与口型。

填写 `.env` 的 `DEEPSEEK_API_KEY` 后重启服务，即可切换「AI 回复」。真实抖音采集仍按原 README 配置 `douyinLive` 与 `cyber-xiaoya-danmaku`；本次未改变平台采集逻辑。

`npm run dev` 只用于前端开发；后端仍需启动，Vite 会把 API 请求代理到 8000。实际直播建议使用 `npm run build` 后的同源服务，避免跨端口写入限制。

## 2. 生成与替换形象

默认显示[写实主播](写实人物.md)。「简易形象工具」中仍可调整肤色、发色和服装，生成并导出简易 GLB。导出文件包含命名节点与口型、眨眼形态键，可重新导入。

真人感主要由模型本身的面部网格、皮肤纹理、头发和材质决定。系统支持加载这些资产；**不包含照片/文字到高保真人体网格的 AI 建模服务**。可以在自己的建模工具中完成模型，再导出 VRM 或 GLB 替换。导入其他模型后，「导出 GLB」仍只导出颜色面板对应的简易人形，不重新打包第三方模型。

### 临时预览

点击「导入 VRM / GLB」，选择自包含文件（建议小于 100 MB）。文件只在本地浏览器读取，不会上传。加载失败保留当前形象；重复选择模型会丢弃旧请求并释放旧模型 GPU 资源。

临时导入不会传递到另一个浏览器、OBS 或页面刷新后的会话。需要持久使用时按下面配置。

### 持久使用与 OBS

1. 将模型放进 `static/models/`，例如 `static/models/host.glb`。
2. 修改 `config/avatar3d.json` 的 `url` 为 `/static/models/host.glb`，并修改 `name`。保留其余字段。
3. 刷新控制台和 OBS 浏览器源，不需要重建前端。

该目录的模型默认被 Git 忽略；静态资源是公开读取路径，不能放入秘密文件。

### 绑定约定

| 格式 | 口型与表情 | 动作 |
| --- | --- | --- |
| VRM 0.x / 1.0 | 标准 `aa`、`blink`、`happy`、`sad`、`angry`、`surprised` 表情 | 标准人形骨架；自动处理 VRM 0 朝向 |
| GLB | 默认支持 `jawOpen` / `mouthOpen` / `viseme_aa`、左右眨眼与微笑等形态键 | 按 `bones` 映射的头、颈、脊柱和上臂节点 |
| 无面部绑定的 GLB | 仍可显示，但不能凭空生成嘴型；页面会提示缺失能力 | 有命名骨骼时可以做轻微程序动作 |

GLB 使用 PBR 材质与灯光；保留原模型的动画，优先播放名为 `idle` 的片段，否则播放第一条。VRM 保留其材质（MToon 模型依然是卡通风格，不会自动变成真人材质）。模型统一缩放到约 1.75 米高度；若反向，设置 `rotationY` 为 `3.141592653589793`。可在画面中拖动旋转、滚轮缩放。

自定义 GLB 骨骼或形态键名称，在 `config/avatar3d.json` 的 `bones` / `morphs` 中映射。嘴型目前按真实音频振幅驱动开合，**不是音素级唇语识别**。高保真口型需要模型具备更细的 viseme 绑定及对应音素数据。

请导出未使用 Draco / Meshopt / KTX2 压缩的自包含 GLB。当前没有接入这些额外解码器；外部纹理必须在同源 `static/models/` 下。2D 的 `TapBody` 礼物动作会映射为通用 3D 手势，烟花、玫瑰雨等继续复用原特效。原来的弹幕「换 Hiyori/Haru」是 Live2D 角色命令；真人模型使用导入或配置文件替换。

## 3. OBS

使用「OBS 人物主体」链接作为浏览器源。

```text
http://127.0.0.1:8000/?obs=1&background=transparent&subject=1
```

建议宽高 `1080 × 1920`（竖屏）或 `1920 × 1080`（横屏）。透明背景使用真实 canvas alpha，也可将 `background` 换成 `green`。去掉 `subject=1` 可显示字幕和礼物特效。浏览器要求手动开启声音时，在 OBS 中选择「交互」，再点击「开启声音」。直播时只保留一个有声播放端。

读取令牌仍使用 `?token=...` 页面入口，后续 API / SSE 通过 `X-Bridge-Token` 发送。远程写接口仍被禁用，不会因为知道只读令牌就能调用 AI。

## 4. 低延迟与稳定性

- 文本接收与 TTS 合成流水线并行，缓冲最多 4 句，避免网络读取被语音合成阻塞。TTS 仍串行，保证顺序与 Piper 线程安全。
- SSE 到达即推送；连接失败自动重连，并用状态查询兜底。同一序号不会重复播放，服务重启会重置播放游标。
- 音频提前下载/解码接下来 3 段；旧音频被清理时返回 404，不会误播最新回复。
- 队列新增事件直接唤醒 worker。默认回复间隔由 3 秒改为 0.3 秒；**已有 `.env` 中的 3 秒不会自动改写**，需要手动调低 `BRIDGE_MIN_INTERVAL`。
- 无标点长句最多 48 字就切出首段，系统 TTS 超时不会永久卡死 worker。
- 3D 初始资源全部本地构建，模型加载器按需加载；VRM 合并骨架、清理无用顶点；默认限制像素密度，可切换 30 FPS 节能模式。FPS 是实测值，选项表示目标上限，不保证所有设备/大模型达到 60 FPS。
- `config/avatar3d.json` 的 `maxFps` / `maxPixelRatio` 是「均衡」档默认值。

页面的「首段音频」是后端开始处理到第一个 WAV 就绪的耗时，不包含排队、网络下载和声卡输出。「排队等待」独立显示；没有测量值时显示 `—`，不会填入估算数据。

## 5. 检查与故障排查

```bash
npm run build
npm test
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
.venv/bin/python tests/access_control.py
.venv/bin/python tests/smoke_bridge.py
.venv/bin/python tools/benchmark_local.py --mode sse --count 5
```

最后一个命令会给正在运行的本机服务发送五条明确的性能检查朗读文本，测量「提交 → 下载到真实 WAV」的本地耗时；不开启 LLM、不写入礼物数据。对比方法和实际结果见 [验证记录](验证记录.md)。

- `503 请先运行 npm ci && npm run build`：前端尚未构建。
- `缺少 DEEPSEEK_API_KEY`：填 `.env` 后重启；直接朗读无需密钥。
- `TTS 后端不可用`：运行 `python tts_backend.py --list-voices`，在 Windows 选择已安装音色，Linux 安装 Piper。
- 选择 `vidu`：保留原云视频分支，但它不提供本地 WAV，3D 页会提示切换本地 TTS；3D 实时直播请使用 `auto/piper/say/sapi`。
- 模型有显示却不张嘴：检查是否真正包含形态键及对应映射；仅贴图/静态网格不能驱动口型。
- 浏览器声音未开启：点击按钮；刷新页面会跳过历史语音，避免重复播报。

## 实测延迟

对照为上游 `362c82d`，在独立端口运行原代码；新版本使用相同机器和系统 `say` / Tingting 音色。连续发送五条同样的检查文本，逐条等到拿到真实 WAV 再提交下一条。上游按原页面的 500ms 间隔轮询，新版本用 SSE。计时范围为「POST 提交到音频下载完成」，不包含声卡播放、LLM 和抖音采集延迟。

| 指标 | 上游 | 3D 分支 |
| --- | ---: | ---: |
| 默认回复间隔 | 3 s | 0.3 s |
| 5 次中位耗时 | 3.5697 s | 0.9145 s |
| 首次无积压耗时 | 1.0132 s | 0.5541 s |
| 后续单次耗时范围 | 3.5626–3.5801 s | 0.8922–0.9235 s |

中位值约减少 74%，主要是调度间隔与推送的改善，**不能解释为 TTS 模型提速 74% 或 AI 全链路提速 74%**。两边 TTS 本身都在约 0.55–0.61 秒。原始测量数据见 [上游 JSON](benchmarks/baseline-local.json) 与 [新版 JSON](benchmarks/3d-local.json)，复现脚本为 `tools/benchmark_local.py`。测试不调用付费服务，不产生虚构礼物/收入数据。

- 正常模型加载与播放页面无控制台错误；断线测试期间的网络错误符合预期。
